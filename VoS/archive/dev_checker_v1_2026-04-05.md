# Dev Checker - Vessels of Sanctuary (VoS)

*Post-change review gate. After any meaningful code change, check this list to see which docs or registries may need updating.*

---

## Checklist

| # | File | Update When |
| :--- | :--- | :--- |
| 1 | `iceberg.md` | A page, component, ability, character, navigation flow, or data schema is added, removed, or restructured. |
| 2 | `dev_ideas.md` | A new feature idea surfaces, an existing idea changes status, or scope estimates are revised. |
| 3 | `issue_tracker.md` | A bug is found or resolved, a regression is introduced, or a known issue's severity changes. |
| 4 | `dev_checker.md` | New documentation files, config files, or registries are added to the project. |
| 5 | `characterData.json` | A new character is added, an existing character's stats/abilities change, or a character is removed. |
| 6 | `index.html` | UI layout changes, new HUD elements added, CSS styling modified, or new screens introduced. |
| 7 | `readme.md` | Project setup steps change, new dependencies added, or core usage instructions are outdated. |
| 8 | `blueprint/` docs | Project scope, design direction, or phase milestones change. |

---

## How to Use

After every meaningful change (new feature, refactor, bug fix, dependency update, or structural reorganization):

1. Review the table above.
2. For each row where the "Update When" condition is true, open the file and update it.
3. Do not consider the work "done" until all affected files are in sync with the codebase.
